# 5월 수불.xlsx ↔ SCM API/DB 매핑 (M1)

기준 파일: `5월 수불.xlsx`  
기획 참고: `기획서_TEMPLATE.md` §2.6, §3.2.1, §4  
현재 구현 스냅샷: `stock_transaction`, `inventory`, `item`, `warehouse`

---

## 1. 확정 정책 (M1)

### 1.1 재고 누적 방식

| 항목 | 결정 |
| --- | --- |
| 스냅샷 키 | **`(item_id, warehouse_id, as_of_date, lot_no)`** — `lot_no` 없으면 `NULL` 단일 버킷 |
| 원장과 재고 | 각 입출고 행은 **거래 기준일 `as_of_date`** 를 가진다. 해당 일자·키의 `inventory.qty`만 증감한다. |
| 서버 `today` 고정 | **폐지 방향** — 현재 코드는 `date.today()`만 갱신하므로 M3에서 **`as_of_date` 기반**으로 일반화한다. |
| 과거일 거래 입력 | 1차: **해당 `as_of_date` 행만** 증감. 그 이후 일자의 잔고를 자동으로 전부 재계산하는 **roll-forward**는 M6·M7 범위에서 옵션으로 검토 (또는 “전 기간 리빌드” 배치). |

### 1.2 재고DB 시트 반영 방식

| 항목 | 결정 |
| --- | --- |
| 방식 | **스냅샷 덮어쓰기(upsert)** |
| 이유 | WMS보내기는 이미 **물리 재고**이므로, 입고·출고 역추적보다 **덤프 기준일의 실재고**를 그대로 맞추는 것이 reconciliation에 유리하다. |
| 구현 방향 | 덤프 **기준일** `as_of_date`를 사용자가 지정(또는 파일 메타). 행마다 `(item_id, warehouse_id, lot_no)` 단위로 `inventory` **해당 일자** 행을 upsert. |
| 로트 | 엑셀 **셀명**(예: `A01-2503`)을 1차 `lot_no`로 매핑하고, 동일 품목·다 로케이션은 별도 행으로 유지한다. |
| 수량 컬럼 | 헤더에 **「재고수량」「가용수량」이 다중 열**로 반복된다. 파서는 (1) 고정 열 인덱스, 또는 (2) **마지막 블록의 가용수량** 등 파일 버전별 규칙을 코드에 명시하고 샘플 행으로 검증한다. (본 파일 샘플: 가용수량 마지막 구간 값이 로케이션별 수량으로 쓰임.) |

### 1.3 출고량 시트 → 원장

| 항목 | 결정 |
| --- | --- |
| 의미 | 일자별 셀 값 = 해당 **일자 OUT 수량** (실적 수요 원천) |
| 변환 | 각 (품목, 일자)에 대해 `trx_type=OUT`, `qty=셀값`(>0일 때만), `as_of_date=열 헤더 일자` |
| 메타 행 | 0~4행(당월일수·가중치 등)은 **스킵**, 5행이 헤더(품목·품목명·전월·평균·일자 열) |

### 1.4 완제품 / 원재료 시트

| 항목 | 결정 |
| --- | --- |
| 성격 | **집계·분석 리포트** (회전월, 소진일, 생산필요 등). 단일 원장이 아님. |
| DB 매핑 | 1차는 **읽기 전용 UI** 또는 기존 `item` + 계산 API 확장으로 흡수. 별도 `fact_sheet` 테이블은 필요 시 M8 이후. |
| 품목 키 | 엑셀 **품목** 숫자 = `item.code`와 문자열 매칭 (`"325230"`). |

### 1.5 BOM 시트

| 항목 | 결정 |
| --- | --- |
| 매핑 | `제품코드` → parent, `자재코드` → child, `소요량` → `qty_per` (기존 `bom`·`bomExcel` 흐름과 동일) |
| 주의 | 행 구조가 제품 헤더 + 자재 들여쓰기 형태 — 기존 파서 규칙 유지 |

## 2. 시트별 컬럼 ↔ 필드 매핑표

### 2.1 `재고DB`

| 엑셀(논리명) | 비고 | 현재 DB/API | 목표(M2~M5) |
| --- | --- | --- | --- |
| 물류센터 | 거점 문자열 | `warehouse` 매핑 (`code` 또는 `name`) | 동일 + 미등록 시 생성/매핑 테이블 |
| 존코드, 로케이션코드, 셀, 셀명 | 위치 | 없음 | `lot_no` 또는 별도 `location_code`(후순위) |
| 화주, 화주명 | WMS 화주코드 | 없음 | 선택 필드 / `source_ref` |
| 품목 | 숫자코드 | `item.code` 조회 | 동일 |
| 품목명, 규격, 단위 | | `item.name`, `item.uom` | 검증·표시용 |
| 재고수량 / 가용수량 (다중 열) | 중복 헤더 | — | **파서 규칙으로 단일 수량 선택** → `inventory.qty` |
| 단가 | | 없음 | 선택 → `item.unit_price`와 혼동 주의, 별도 컬럼 권장 |

### 2.2 `출고량`

| 엑셀(논리명) | 비고 | 현재 DB/API | 목표(M4) |
| --- | --- | --- | --- |
| 품목 | 코드 | `item_id` | 동일 |
| 품목명 | | 표시 | 동일 |
| 전월 출고량, 평균 출고량 | 집계 | 없음 | 리포트/검증용 선택 저장 |
| 각 일자 열 (datetime 헤더) | 일별 출고 | 없음 | `stock_transaction` OUT + `as_of_date` |

### 2.3 `완제품` (데이터 행 예: 7행~)

| 엑셀(논리명) | 현재 DB/API | 목표 |
| --- | --- | --- |
| 구분 | — | 표시 |
| 품목 | `item.code` | 동일 |
| 품목명, 규격, 원가(원) | `item` / 가격 | 동일 |
| 현재고, 재고금액(원) | `inventory` 집계 vs 엑셀 비교 | M6 reconciliation |
| 월 출고량, 회전월, 예상 소진일, 소비기한, 생산… | 계산 결과 | 대시보드·52주·별도 리포트 API |
| 월 생산량 / 월별 출고량 (연도별 열) | `production_plan` 등 | 단계적 연동 |

### 2.4 `원재료` (데이터 행 예: 7행~)

| 엑셀(논리명) | 현재 DB/API | 목표 |
| --- | --- | --- |
| 품목, 품목명, 규격, 원가 | `item` | 동일 |
| 현재고(계), 다중 로트 소비기한 열 | `inventory` + lot | M2~M5 |
| 월 사용량, 회전월, 리드타임, MOQ | `item`·계산 | 기존 필드·MRP와 정합 |
| 월별 사용량 (2024/2025) 열 | 없음 | 수요 히스토리(선택) |

### 2.5 `stock_transaction` (목표 스키마 — M2에서 반영)

| 필드 | 엑셀 출처 예시 |
| --- | --- |
| `as_of_date` | 출고량: 열 헤더 일자 / 수동입력 / 재고DB 덤프일 |
| `item_id`, `warehouse_id` | 품목·물류센터 |
| `trx_type` | IN / OUT / (ADJUST는 정책 문서화 후) |
| `qty` | 수량 |
| `unit` | 단위 (EA 등) |
| `lot_no`, `expiry_date` | 재고DB 셀명·소비기한 / 비고 |
| `source_ref` | 파일명·시트·행, BL 등 |
| `reason` | 자유 메모 (기존 호환) |
| `trx_time` | 서버 기록 시각 (감사) |

### 2.6 `inventory` (현재 vs 목표)

| 필드 | 현재 | 목표 정합 |
| --- | --- | --- |
| `item_id`, `warehouse_id`, `as_of_date`, `lot_no`, `qty`, `expiry_date` | ✓ | 재고DB upsert·원장 증감과 동일 키 사용 |
